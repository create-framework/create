# Glossary

| Term | Meaning |
|---|---|
| Screen space | Origin-centred, y-up, camera-independent. `canvas.left()`…`top()`, `context.mouse.position` and `canvas.color_at` live here, and it is what `canvas.to_local` takes and `to_screen` gives |
| World space | What render calls use once a `Camera` is set; identical to screen space without one. Only the camera converts into it: `camera.to_world`/`to_screen` |
| Local space | The current transform's frame, where a render call's coordinates are read. `canvas.to_local(screen)`/`to_screen(local)` convert through the transform and the camera together |
| Asset vs. playhead | `Image`/`Font`/`Animation`/`Sound` are shared immutable assets; `Animator`/a `Voice` (what `audio.play` and `audio.loop` return) are one entity's position in one. `fps` belongs to the asset |
| `Easing` / `Tween` | An `Easing` is a stateless curve over a 0-to-1 fraction (`ease(curve, t)`); a `Tween` walks that fraction over a duration. Each entity owns its own `Tween`. Frame-by-frame animation is `Animation`/`Animator` (in `image`), not a tween |
| `Time` / `DateTime` | `context.time` is the run's clock: ticked by the loop, zero at the first frame, synthetic in headless runs. `DateTime.now()` is the computer's local wall clock, read once into consistent fields (`year` … `millisecond`) — take one reading per frame rather than calling it per field |
| `Random` / `Noise` | Both seeded, both in `[0, 1]`. `Random` is stateful (`mut`, `Movable`): each call is an independent sample. `Noise` is immutable (`Copyable`): `at(...)` is a pure function of its input, and nearby inputs give nearby values. `feature_size` divides space only; `at(position, time)` leaves `time` for the caller to scale. Averaged octaves cluster around 0.5 — stretch with `smoothstep` for contrast |
| `Gradient` | Stops (0..1 positions, each a `Color`) across a fill or the background. **Placed by the shape's local bounding box**, before the transform, so it moves and turns with the shape and one `Style` suits every entity. `linear` runs along `direction` (a `Vector2D`, default `DOWN`, any length; its extreme corners land on 0 and 1, as in CSS); `radial` runs from `center` in the box's unit space (-1..1, y up) out to its edges, an ellipse on a long box. A sector's box is its whole circle. A zero `direction` or a zero-size box paints the first stop. Blends premultiplied (a fade to `TRANSPARENT` stays clean) and is dithered on both backends |
| `Table` | Rows of text cells from CSV/TSV, like Processing's: `Table.load(path)` (first line names the columns unless `header=False`; separator a tab for `.tsv`/`.tab`, a comma otherwise, unless `separator=` names one), `Table.parse(text)`, `Table(columns)` to build. **Rows by reference**: `t.row(i)` and `for ref row in t.rows()` edit in place; `ref row = t.add_row()` returns the new one. Cells stay text until read: `row.string`/`float`/`int`/`bool` by column name or index parse on each call and raise naming the column and cell. `sort(column, descending=)` is stable and numeric only when every cell in the column is a number, so one blank sorts the column as text. `save` quotes a field only when it must |
| `JSON` | One type for every JSON value, read with `[]` by key or index and `float`/`int`/`string`/`bool`; `kind()` is a `JSONKind`. `values()` is an array's items or an object's values, `keys()` an object's keys and `items()` its `(key, value)` pairs, as in Python. A value is a **handle into a shared document**: `[]`, `values()` and `items()` copy nothing, edits land in the document (`config["player"]["speed"] = 3.0`, or `enemy["hp"] = ...` in a loop over `values()`), and so **`var p = config["player"]` aliases `config`**, as in Processing, JavaScript and Python — `.copy()` is a deep, independent one. Assigning copies a value in, so one value set under two keys is two values. `int()` is exact to 64 bits for a number written whole and raises on a fraction. Replacing a value leaves the old node behind until `copy()` or `save` drops it, so a document rewritten every frame for long is kept small with `doc = doc.copy()`. `save(path, indent=2)`; `indent=0` is the printed form. Infinite and NaN numbers raise from `save`, print as `null` |
| `Point2D` / `Vector2D` | Chosen by role. A location is a `Point2D` (`canvas.circle(position, r)`, `context.mouse.position`); a displacement is a `Vector2D` (`translate(delta)`, velocities); an extent is a scalar (`w`, `h`, `r`). Crossing between them is an explicit constructor — `Vector2D(p)`, `Point2D(v)` — never an implicit one. `Point2D` deliberately lacks `magnitude`, `normalize`, `dot`, scalar `*`, unary `-` and `Point2D + Point2D`. Only `Point2D` takes a bare tuple implicitly; a vector literal names its type (`p + Vector2D(1, 2)`), and `p - (1, 2)` is the displacement from `(1, 2)`, not a move. Named vectors are `comptime` constants: `Vector2D.ZERO`, `ONE`, `UP`, `DOWN`, `LEFT`, `RIGHT` (y up, so `DOWN` is `(0, -1)`). Angles are radians counter-clockwise from +x: `Vector2D.from_angle(a, length)`, `v.angle()`, `v.rotate(a)`, with `v.with_length(l)` and `v.limit(max)` for speeds; each returns a new vector, like `normalize` |
| Down / pressed / released | One vocabulary for every device: `context.keyboard`, `context.mouse` and `context.gamepad(i)` each answer `down(button)`, `pressed(button)` and `released(button)` (the mouse's default to `LEFT`). *Down* is held right now, true every frame; *pressed*/*released* are edges, true only in the frame it went down or came up. Unlike Processing's `mousePressed`, *pressed* never means held. When the window loses focus everything held is released, each with its *released* edge, since what is let go while it is away is never reported to it; a disconnecting pad releases its buttons the same way. The most recent press is `keyboard.key`, `mouse.button` and `pad.button`, each `Key`/`MouseButton`/`GamepadButton.NONE` before any — typed, like every enum, so a bare number never passes for a key, button or `FontWeight` |
| `Gamepad` | `context.gamepad(i)`, a copy of player `i`'s pad (default 0). A pad takes the lowest free slot as it connects and keeps it until it disconnects; an empty slot reads `connected` False and all zero, so no check is needed first. Sticks are `Vector2D`s, **y up**, inside the unit circle, with a rescaled radial dead zone (`Gamepad.STICK_DEAD_ZONE`, 0.2) so a resting stick reads exactly zero; triggers 0..1. Face buttons are positional (`GamepadButton.SOUTH` is Xbox A and PlayStation Cross). Each trigger is also a button, `GamepadButton.LEFT_TRIGGER`/`RIGHT_TRIGGER`, down from `Gamepad.TRIGGER_PRESS` (0.5) and up again below `TRIGGER_RELEASE` (0.4), so `pad.pressed(GamepadButton.RIGHT_TRIGGER)` fires once per pull. `connected_this_frame`/`disconnected_this_frame` are the edges of `connected`, and `name` survives the frame a pad leaves in. `context.rumble(seconds, low_frequency=, high_frequency=, player=)` shakes a pad (both motors full by default; a new rumble replaces the running one); it is an output, so it lives on `Context`, not on the `Gamepad` copy. See [examples/gamepad/main.mojo](../examples/gamepad/main.mojo) |
| `Mouse` | `context.mouse`: `position` and `press_position` (`Point2D`s, screen space), `wheel` (this frame's scroll, added up) and `movement` (how far the pointer moved this frame, y up, in screen units). `movement` keeps counting where `position` stops — at the screen's edge, and while `context.lock_mouse(True)` hides the pointer and holds it in the window for a first-person camera; unlock it for a menu. `context.cursor(...)` sets the pointer's look |
| `Key` | A key **by position**, not by label: each constant names where a key sits on a US layout, so `Key.W` is the key above `S` (AZERTY's Z) and WASD lands under the same fingers on every layout. Characters never come from a `Key`; they are `context.keyboard.text`. `Key.from_name` reads a binding from a file (`"page_up"`, `"a"`, `"/"`), as do `MouseButton.from_name`, `GamepadButton.from_name` and `Cursor.from_name`, each by its constants' names, case folded. `CTRL`/`SHIFT`/`ALT`/`SUPER` match either side |
| Typed / `text` | Text entry. `keyboard.typed(key)` is pressed or auto-repeated while held, for editing keys (Backspace, arrows); `context.keyboard.text` is this frame's typed characters, UTF-8, with shift, layout and IME applied — append it, don't rebuild it from keys. Both reset every frame. Taking text is on by default and also opens an IME's composition window and a handheld's on-screen keyboard, so a game played on letter keys switches it off with `context.text_input(False)` (keys read the same; only `text` goes quiet) and on again while a field is in use. `EditableText` does the editing: `field.update(context)` each frame replays the frame's typing in the order it came (so text and keys typed within one frame land where they were typed) and keeps `text`, a caret and a selection, whole characters at a time — Shift extends the selection, a word modifier (Option on macOS, Ctrl elsewhere) moves and deletes by words, and the command shortcuts (Cmd on macOS, Ctrl elsewhere; by the key's label, not its position) select all, copy, cut and paste through `context.clipboard()`/`context.clipboard(text)`, the system clipboard. `max_length=` caps what typing and pasting add. `canvas.text_width(field.before_caret())` places the caret, `before_selection()`/`selected_text()` the selection's highlight. It lives in `core`, beside the `Context` it reads. See [examples/typing/main.mojo](../examples/typing/main.mojo) |
| `overlaps` / `intersects` / `contains` | `overlaps(a, b)`: free, symmetric, regions only (`Rectangle`/`Circle`/`Ellipse`/`Capsule`/`Triangle`/`Sector`/`Polygon`). `curve.intersects(x)`: every curve (`Line`, `Arc`, `Bezier`, `Spline`) against every shape and `Point2D`, both ways round, since a curve has no interior. `region.contains(x)`: asymmetric, every region against every region and every curve. A curve is never a region. All three see a shape's `corner_radius`. `Line` and `Arc` are exact (to `_RADIUS_EPSILON` with an arc); `Bezier` and `Spline` flatten themselves to within 1e-4 of their size, so a crossing is always found but a graze or near miss is decided only that closely; a region's `contains` follows `Arc`, `Bezier` and `Spline` the same way |
| `Drawable` / `DrawTarget` | `Drawable` is what `canvas.draw` takes: every shape, or a program's own type that draws its parts (`draw_to[T: DrawTarget](self, mut target: T)`). `DrawTarget` is where it draws: `Canvas`, through one `_`-named primitive per kind and the provided `draw` |
| `Shape` / `Region` / `Curve` | The geometry's traits, so every shape of a kind answers the same methods and generic code takes any (`def f[C: Curve](c: C)`). `Shape(Drawable)`, every one of the eleven, `Copyable` and `Deinitable`: `bounds`, `closest_point`, `translate`. `Region(Shape)`, the seven with an inside (`Rectangle`, `Circle`, `Ellipse`, `Capsule`, `Triangle`, `Sector`, `Polygon`), which `canvas.clip` takes: `center`, `area`, `contains(Point2D)`, `move_to`. `Curve(Shape)`, the four without (`Line`, `Arc`, `Bezier`, `Spline` — a straight line is a curve, as in mathematics): `at`, `tangent` (the derivative, not unit), `length`, `at_distance`, `flatten`, `beziers`. Tests between two shapes (`overlaps`, `contains(shape)`, `intersects`) stay overloads per pair, so they are not trait methods; nor is a curve's `move_to`, which only `Line` (its midpoint) and `Arc` (its centre) have, or `split(t)`, which `Line`, `Arc` and `Bezier` have — a piece of a `Spline` is not a `Spline` |
| `Rectangle` | Centre-positioned, `w` by `h`, upright unless turned: `rotation=` (keyword-only, radians counter-clockwise about `position`, default 0) on `Rectangle` and `canvas.rectangle`. Every test sees the turned shape exactly; `bounds()` and `left()`/`right()`/`bottom()`/`top()` are its upright bounding box's. Drawn as the upright rectangle under a rotation, so rounding, stroke and a gradient turn with it and a shadow's offset stays screen-fixed, as under `canvas.transform` |
| `corner_radius` | A keyword-only field of `Rectangle`, `Triangle`, `Polygon` and `Sector` (`Rectangle(p, w, h, corner_radius=8)`): a shape value is drawn and clipped by its own radius, whatever the style says. The scalar canvas calls (`rectangle`, `triangle`, `polygon`, `sector`) take a `corner_radius=` keyword, and without one use the style's: `canvas.corner_radius(r)`, `Style(corner_radius=)`, `canvas.style(corner_radius=)`. A named keyword beats the style, `corner_radius=0` included. Clamped as drawn: a rectangle to half its shorter side, a triangle's one radius so no corner overruns half an edge; a polygon's and a sector's corners each on their own, a concave corner filling its notch. Every `contains`/`overlaps`/`intersects`/`closest_point`/`area` sees it: rectangles and triangles exactly, polygons and sectors through their stroke with each curve flattened (within ~0.1% of the radius). A rounded polygon or sector draws as a polygon of more vertices, so it costs more stroked (see `Polygon`) |
| Sweep | `Arc` and `Sector` share `position` (the circle's centre), `r`, `start_angle` and a **signed** `sweep_angle`, in radians from +x: positive is counter-clockwise (y is up), negative clockwise, and \|sweep\| ≥ `TAU` is the whole circle. Stored as given, so `==` and printing round-trip; `end_angle()` is `start_angle + sweep_angle` |
| `Arc` | A curve, like `Line`: no interior, never in `overlaps`. Constant speed, so `at_distance(d)` is exact. `beziers()` splits it into Béziers of at most 45°; `canvas.arc` strokes those as one chain, like `canvas.spline` |
| `Ellipse` | Axis-aligned, a region: `position` its centre and `w`/`h` its full width and height, as a `Rectangle`'s, whose `bounds()` it fills (`canvas.ellipse(p, w, h)`, Processing's `ellipse`); turn one with `canvas.transform`. Tests against a point, `Line`, `Circle`, another `Ellipse` and a sharp `Rectangle`/`Triangle`/`Polygon` are exact — the stretch onto the unit circle keeps those kinds, and a circle or ellipse goes through the exact closest point on an ellipse; against a `Sector` or an `Arc` the ellipse stands in as its outline polygon, within 1e-4 of its size. A zero `w` or `h` is its zero-size bounds, in every test and when drawn. Drawn as a polygon flattened as finely as a circle of its larger radius, so its stroke is as thick all round and placed by `stroke_alignment`; filled, it costs what a circle does, stroked about three times as much; no inset shadow |
| `Capsule` | Every point within `r` of the segment `start`→`end`, a region: the round collider for a moving body, at any angle (`canvas.capsule(start, end, r)`). Placed by its ends like a `Line`, so `center()` and `move_to` are the midpoint's; `start == end` is the `Circle` there, and a stadium is already `Rectangle(p, w, h, corner_radius=h / 2, rotation=a)`. Every test is a distance from the segment, exact against everything — points, lines, arcs, circles, ellipses, capsules, straight-edged shapes and rounded rectangles and triangles — except holding a `Sector`'s arc or an `Ellipse`, which it follows within 1e-4. A zero `r` is the segment, and draws nothing. Drawn as a polygon, each end flattened as finely as a circle of `r`, its gradient spanning its bounds; filled it costs what a circle does, stroked about 2.3 times as much; no inset shadow |
| `Sector` | A pie slice, a region: its tip at `position`, fanned out to its arc. Wider than a half turn it is not convex — the missing wedge is outside it, for `contains` and `overlaps` alike. `center()` is `position`, like `Circle`'s, not the centroid. `canvas.sector` places its stroke by `stroke_alignment`, as a circle's; no inset shadow. `corner_radius` rounds the tip and both ends of the arc, the ends tangent to the arc from inside; past a half turn the tip is concave and its rounding fills the notch, at exactly a half turn it runs straight and stays, and a whole disc has no corners |
| `Polygon` | Any `vertices`, in order, closed back to the first: concave or crossing itself, a region. Inside by the **nonzero rule** (a pentagram of five crossing vertices is solid through its middle), vertex order irrelevant, boundary inside. `Polygon.regular(position, r, sides)` and `Polygon.star(position, r, inner_radius, tips)` start at `start_angle`, straight up by default. `center()` is the area centroid and `area()` the shoelace area, both meaningful only for a simple polygon. `canvas.polygon` places its stroke along the outside by `stroke_alignment` but centres it on an edge running through the inside (a pentagram's inner pentagon), so every edge is stroked as thick; no inset shadow. `corner_radius` rounds every vertex (not the crossings of a self-crossing one). Stroked, on the CPU at `MEDIUM`, a 5-tip star costs ~160 µs a frame, a pentagram ~380 µs, a 40-tip star ~2 ms; rounded, ~360 µs, ~460 µs and ~20 ms. Filled only, a fraction of that |
| `Bezier` | A cubic Bézier: `start`, `control1`, `control2`, `end`; passes through the endpoints only. A curve, not a region: `canvas.bezier` strokes it in the stroke style and draws nothing with the stroke off. `at(t)` is uneven in speed; `at_distance(d)` moves along it at constant speed. `closest_point` is a search (samples, then Newton), accurate to rounding |
| `Spline` | A smooth curve through every one of `points`, in order (Catmull-Rom); `closed` runs it on back to the first. `alpha` spaces its knots: 0 uniform (can loop where points bunch), 0.5 centripetal (default, never does), 1 chordal. Same sampling methods as `Bezier`, `t` split evenly per stretch. `beziers()` converts it exactly; `canvas.spline` draws it as one stroke of those Béziers |
